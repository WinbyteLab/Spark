### Целевая архитектура

| Устройство | Роль | Подключение |
| :--- | :--- | :--- |
| **Geekom A8 Max (Windows)** | Клиент, шлюз в интернет | **Wi-Fi** (доступ в интернет) + **Ethernet** (прямое соединение с DGX Spark) |
| **DGX Spark (Linux)** | Сервер (vLLM, Qwen3.8-27B) | **Только Ethernet (RJ45)**. Wi-Fi **отключён** |

---

### Шаг 1: Физическое подключение

1.  Соедините DGX Spark и Geekom A8 Max кабелем Ethernet (RJ45) **напрямую** (без роутера или коммутатора).
2.  **Не подключайте** DGX Spark к Wi-Fi. Если он был подключён ранее, переходите к Шагу 2, чтобы отключить беспроводной интерфейс.

---

### Шаг 2: Отключение Wi-Fi на DGX Spark

Это можно сделать двумя способами. Первый — надёжный и постоянный, второй — быстрый, но требующий повторения после перезагрузки.

#### Вариант A: Полное отключение через UEFI (рекомендуемый)

Этот метод отключает беспроводной модуль на уровне прошивки, что гарантирует, что Wi-Fi не будет активирован даже после обновлений или сбросов настроек ОС.

1.  Перезагрузите DGX Spark.
2.  Сразу после начала загрузки **многократно нажимайте `Esc` или `Del`**, чтобы войти в меню UEFI.
3.  Перейдите в **Advanced → Advanced Menu → IO Port Access**.
4.  Найдите параметр **Wireless LAN & Bluetooth** и установите его в значение **Disabled**.
5.  Сохраните изменения и выйдите из UEFI.

После этой процедуры беспроводные интерфейсы будут полностью недоступны для операционной системы.

#### Вариант B: Программное отключение в Linux

Если вы не хотите менять настройки UEFI, можно отключить Wi-Fi средствами ОС. Этот метод не постоянный, и после крупного обновления системы настройки могут сброситься.

Выполните в терминале DGX Spark:
```bash
# Отключить и заблокировать беспроводной интерфейс
sudo nmcli radio wifi off
sudo nmcli radio wifi disable

# Проверить, что Wi-Fi выключен
nmcli radio wifi
```
Ожидаемый вывод: `disabled`. Также убедитесь, что беспроводной интерфейс (например, `wlan0` или `wlP9s9`) не имеет IP-адреса командой `ip -br addr`.

---

### Шаг 3: Настройка общего доступа к интернету (ICS) на Geekom A8 Max

Эта функция позволит Geekom делиться своим Wi-Fi-интернетом с DGX Spark через Ethernet-порт. При этом Geekom автоматически станет DHCP-сервером и шлюзом для DGX Spark.

1.  На **Geekom A8 Max** нажмите `Win + R`, введите `ncpa.cpl` и нажмите Enter, чтобы открыть окно сетевых подключений.
2.  Найдите ваш **Wi-Fi адаптер** (через который есть интернет). Нажмите на него правой кнопкой мыши → **«Свойства»**.
3.  Перейдите на вкладку **«Доступ»**.
4.  Поставьте галочку **«Разрешить другим пользователям сети использовать подключение к Интернету данного компьютера»**.
5.  В выпадающем списке **«Подключение домашней сети»** выберите ваш **Ethernet-адаптер** (тот, к которому подключён кабель от DGX Spark).
6.  Нажмите **«ОК»**. Windows предупредит, что Ethernet-адаптеру будет присвоен статический IP-адрес **`192.168.137.1`**. Согласитесь.

---

### Шаг 4: Настройка сети на DGX Spark

После включения ICS на Geekom, DGX Spark должен автоматически получить IP-адрес из подсети `192.168.137.x` по DHCP.

1.  В терминале DGX Spark выполните команду, чтобы узнать имя проводного интерфейса и его IP-адрес:
    ```bash
    ip -br addr
    ```
    Найдите интерфейс, скорее всего, `enP7s7` (или `enp1s0f0np0`), и убедитесь, что у него есть адрес вида **`192.168.137.xxx`**.

2.  **Проверьте связь с Geekom** (шлюзом):
    ```bash
    ping 192.168.137.1
    ```
    Если пинг проходит, значит прямое соединение работает.

#### Если IP-адрес не присвоился автоматически

Иногда DHCP от ICS может не сработать. В этом случае назначьте статический IP-адрес вручную через Netplan. **Важно:** не редактируйте существующие файлы Wi-Fi, создайте новый.

1.  Создайте новый файл конфигурации (замените `enP7s7` на ваше имя интерфейса):
    ```bash
    sudo tee /etc/netplan/99-direct-ethernet.yaml > /dev/null <<'EOF'
    network:
      version: 2
      ethernets:
        enP7s7:
          dhcp4: false
          dhcp6: false
          addresses:
            - 192.168.137.2/24
    EOF
    ```
    > **Ключевой момент:** Мы **не указываем** `gateway` и `routes` (шлюз по умолчанию), чтобы DGX Spark не пытался выйти в интернет через этот интерфейс. Он должен знать только о локальной подсети.

2.  Установите права и примените конфигурацию:
    ```bash
    sudo chmod 600 /etc/netplan/99-direct-ethernet.yaml
    sudo netplan try
    ```

### Шаг 5: Проверка полной изоляции и доступности

1.  **Проверьте IP-адрес** на DGX Spark:
    ```bash
    ip -br addr show enP7s7
    ```
    Ожидается `192.168.137.2/24` (или адрес, полученный по DHCP).

2.  **Проверьте доступность из локальной сети** (с Geekom A8 Max). Откройте PowerShell или командную строку и выполните:
    ```powershell
    ping 192.168.137.2
    ```
    Пинг должен проходить.

3.  **Проверьте отсутствие доступа в интернет** с DGX Spark:
    ```bash
    curl -I --max-time 5 https://www.google.com
    ```
    Ожидаемый результат: **таймаут** или ошибка соединения. Это подтверждает, что DGX Spark изолирован от глобальной сети.

4.  **Проверьте, что Wi-Fi на DGX Spark действительно отключён**:
    ```bash
    nmcli radio wifi
    ```
    Команда должна вернуть `disabled`. Также убедитесь, что в выводе `ip -br addr` отсутствует беспроводной интерфейс с IP-адресом.

###  Устранение неполадок

| Проблема | Вероятная причина | Решение |
| :--- | :--- | :--- |
| **DGX Spark не получает IP `192.168.137.x`** | DHCP от ICS не сработал | Настройте статический IP вручную (Шаг 4). |
| **Нет пинга между устройствами** | Кабель неисправен или интерфейс не активен | Проверьте кабель, выполните `sudo ethtool enP7s7` — строка `Link detected` должна быть `yes`. |
| **Hermes Agent не подключается к vLLM** | Указан неверный IP-адрес DGX Spark | Используйте IP, который вы получили на Шаге 4 (`192.168.137.2` или DHCP-адрес). URL должен быть `http://192.168.137.2:8000/v1`. |
| **После перезагрузки DGX Spark снова в Wi-Fi** | Использован только программный метод отключения (Вариант B) | Выполните полное отключение через UEFI (Вариант A). |
