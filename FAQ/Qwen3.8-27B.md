## Qwen3.8-27B на DGX Spark через vLLM

**Вопрос 1. Что представляет собой Qwen3.8-27B?**
Это **27-миллиардная плотная (dense) модель** семейства Qwen3.8 с гибридным вниманием: только 16 из 64 слоёв используют полное внимание, а 48 слоёв — линейное внимание с постоянным рекуррентным состоянием. Модель является **мультимодальной** (архитектура `Qwen3_5ForConditionalGeneration`) и имеет нативное контекстное окно **262 144 токена** с возможностью расширения до 1 млн.

**Вопрос 2. Почему для DGX Spark рекомендуется именно вариант NVFP4?**
NVFP4 — это 4-битный формат квантования, оптимизированный для архитектуры Blackwell. В этом формате Qwen3.8-27B занимает около **24,6 ГиБ**, что позволяет модели комфортно разместиться в 128 ГБ унифицированной памяти DGX Spark и оставить значительный запас для KV-кэша и других задач.

**Вопрос 3. Сколько памяти занимают веса модели в NVFP4?**
По разным оценкам, веса Qwen3.8-27B (Dense) в NVFP4 занимают примерно **16,5 ГБ**, а полный занимаемый объём с учётом всех компонентов составляет около **24,6 ГиБ**. Это оставляет порядка 40 ГБ и более под KV-кэш и служебные нужды.

**Вопрос 4. Какой минимальный набор компонентов нужен для запуска модели?**
Docker с поддержкой NVIDIA GPU, контейнер с vLLM (версия 0.17.0 или новее) и загруженные веса модели. Официальный рецепт от vLLM для DGX Spark (GB10) является проверенным и рекомендуется как отправная точка.

**Вопрос 5. Какую команду `vllm serve` использует официальный рецепт для DGX Spark?**
Проверенная конфигурация для одного DGX Spark (GB10) выглядит так:
```bash
export VLLM_USE_RUST_FRONTEND=1
vllm serve Qwen/Qwen3.8-27B \
  --max-num-seqs 8 \
  --gpu-memory-utilization 0.8 \
  --tensor-parallel-size 1 \
  --enable-auto-tool-choice \
  --tool-call-parser qwen3_coder \
  --reasoning-parser qwen3 \
  --mm-encoder-tp-mode data
```


**Вопрос 6. Что означает параметр `--gpu-memory-utilization 0.8`?**
vLLM будет использовать до **80%** доступной памяти GPU (в случае DGX Spark — унифицированной памяти) для модели и KV-кэша. Оставшиеся 20% резервируются для системных нужд и других процессов.

**Вопрос 7. Зачем нужен `--tensor-parallel-size 1`?**
Это означает, что модель не разрезается между несколькими GPU, а целиком размещается на одном GB10. Для одного DGX Spark это корректная настройка.

**Вопрос 8. Что делают парсеры `qwen3_coder` и `qwen3`?**
`--tool-call-parser qwen3_coder` включает корректную обработку вызовов инструментов (tool calling), что критически важно для работы Hermes Agent. `--reasoning-parser qwen3` обеспечивает поддержку режима рассуждений (reasoning) модели.

**Вопрос 9. Почему рецепт рекомендует `VLLM_USE_RUST_FRONTEND=1`?**
Экспериментальный Rust-фронтенд vLLM может повысить пропускную способность и снизить задержку, особенно при высокой конкурентности запросов. Если вы столкнётесь с несовместимостью или отсутствием нужных функций, можно переключиться на Python-фронтенд.

**Вопрос 10. Как проверить, что vLLM-сервер запустился и API доступен?**
Выполните на DGX Spark:
```bash
curl -sS http://localhost:8000/v1/models
```
В ответе должен быть JSON-массив `data` с идентификатором обслуживаемой модели. Это стандартная проверка OpenAI-совместимого эндпоинта.

**Вопрос 11. На каком порту по умолчанию работает vLLM?**
По умолчанию vLLM слушает порт **8000**. Именно на этот порт нужно будет настроить Hermes Agent (с указанием `/v1` в конце URL).

**Вопрос 12. Обязательно ли использовать Docker?**
Официальные рецепты vLLM для DGX Spark предполагают запуск в контейнере, но технически можно установить vLLM и в виртуальное окружение. Однако контейнерный путь является **проверенным и воспроизводимым**, поэтому рекомендуется именно он.

**Вопрос 13. Можно ли использовать другой формат квантования, например FP8 или INT4?**
Да, рецепт vLLM предлагает варианты FP8, INT4 и MXFP4. Однако для одного DGX Spark официально рекомендован именно **NVFP4** как оптимальный по соотношению «занимаемая память / производительность».

**Вопрос 14. Что делать, если модель не помещается в память?**
Уменьшите `--gpu-memory-utilization` (например, до 0.7) или сократите `--max-model-len`. NVFP4-версия занимает около 24,6 ГиБ, поэтому в 128 ГБ она должна помещаться с большим запасом, но KV-кэш для длинного контекста может занимать значительный объём.

**Вопрос 15. Как обеспечить доступ к API vLLM с другого компьютера (Geekom A8 Max)?**
vLLM по умолчанию может слушать только `localhost`. Чтобы сделать его доступным по сети, при запуске добавьте флаг `--host 0.0.0.0`. **Обязательно** убедитесь, что порт 8000 открыт в брандмауэре DGX Spark.

**Вопрос 16. Какие риски безопасности связаны с `--host 0.0.0.0`?**
Открытие порта vLLM на все интерфейсы делает API доступным любому в локальной сети. Если в вашей сети есть недоверенные устройства, рассмотрите использование обратного прокси с аутентификацией или ограничьте доступ по IP. Для домашней лаборатории это приемлемый компромисс, но для офисной сети — требует оценки рисков.

**Вопрос 17. Поддерживает ли Qwen3.8-27B вызов инструментов (tool calling)?**
Да, и это критически важно для Hermes Agent. Именно поэтому в команде запуска присутствуют `--enable-auto-tool-choice` и `--tool-call-parser qwen3_coder`. Без них агент не сможет корректно использовать инструменты.

**Вопрос 18. Можно ли увеличить контекстное окно свыше 262K?**
Модель поддерживает расширение до **1 млн токенов**, но это потребует значительного объёма KV-кэша. На одном DGX Spark с 128 ГБ памяти увеличение контекста сокращает доступную память для других задач. Начните со стандартных 262K и увеличивайте только при необходимости.

**Вопрос 19. Как обновить vLLM или сменить модель?**
Остановите текущий контейнер (Ctrl+C), затем запустите новый с обновлённым тегом образа или другим идентификатором модели. Hermes Agent после этого нужно перенастроить на тот же URL — он увидит новую модель через `hermes model`.

**Вопрос 20. Что такое MTP (Multi-Token Prediction) и стоит ли его включать?**
MTP — это встроенная в Qwen3.8-27B голова спекулятивного декодирования, которая может ускорить генерацию. В рецепте vLLM для её активации используется `--speculative-config '{"method":"mtp","num_speculative_tokens":3}'`. Включайте, если хотите снизить задержку, но следите за потреблением памяти.

**Вопрос 21. Нужен ли API-ключ для локального vLLM?**
По умолчанию vLLM не требует API-ключа. Hermes Agent при подключении к кастомному эндпоинту может запросить ключ — в этом случае можно ввести любую заглушку (например, `not-needed`). Если вы запускаете vLLM с флагом `--api-key`, используйте именно этот ключ.

**Вопрос 22. Как мониторить использование памяти и GPU во время работы vLLM?**
Поскольку `nvidia-smi` не показывает память на DGX Spark, используйте `free -h`, `htop` или DGX Dashboard (`https://localhost:11000`). Для мониторинга загрузки GPU можно использовать `nvtop`, если он установлен.

**Вопрос 23. Какая версия transformers требуется для Qwen3.8-27B?**
Требуется **`transformers >= 5.8.0`**, чтобы соответствовать версии, с которой был записан `config.json` модели (для классов процессора Qwen3-VL). vLLM использует собственный `Qwen3_5Config`, но установка правильной версии transformers важна для корректной работы с мультимодальными компонентами.

**Вопрос 24. Что делать, если vLLM падает с ошибкой нехватки памяти при загрузке?**
Убедитесь, что используется именно NVFP4-версия (она значительно компактнее BF16). Если ошибка сохраняется, проверьте, не занята ли память другими процессами (`free -h`), и при необходимости очистите кэш. Также можно снизить `--gpu-memory-utilization`.

**Вопрос 25. Где найти официальный рецепт vLLM для Qwen3.8-27B на DGX Spark?**
Прямая ссылка: `recipes.vllm.ai/Qwen/Qwen3.8-27B?hardware=dgx_spark_gb10`. Дополнительная точка входа — `build.nvidia.com/station/vllm/choose-recipe`, где можно выбрать конфигурацию «One DGX Spark» и получить рекомендованный рецепт.
