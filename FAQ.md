## Тема 1: NVIDIA DGX Spark (GB10, 128 ГБ)

**Вопрос 1. Что такое DGX Spark по своей сути?**
DGX Spark — это настольный мини-суперкомпьютер для локального запуска и тонкой настройки ИИ-моделей, а не игровая станция. Он построен на суперчипе GB10 Grace Blackwell и позиционируется как устройство, способное заменить рабочую станцию за $30 000 для задач инференса.

**Вопрос 2. Какая операционная система установлена на DGX Spark?**
Базовая ОС — **Ubuntu 24.04 LTS (arm64)** в серверной редакции с добавленными пакетами рабочего стола. Поверх неё развёрнута **NVIDIA DGX OS**, которая управляет версиями ядра и драйверов.

**Вопрос 3. Какая версия ядра Linux используется?**
Версия ядра зависит от релиза DGX OS. В актуальных сборках (DGX OS 7.6.0 и новее) используется **Canonical Kernel 7.0.0-1019**. В более ранних версиях встречались ядра 6.17 и 6.11. Точную версию на вашем устройстве покажет команда `uname -r`.

**Вопрос 4. Какая архитектура у процессора DGX Spark?**
20-ядерный Arm CPU: 10 высокопроизводительных ядер **Cortex-X925** и 10 энергоэффективных **Cortex-A725**.

**Вопрос 5. Какая GPU используется и сколько в ней ядер CUDA?**
GPU на архитектуре **Blackwell** с **6 144 ядрами CUDA** и тензорными ядрами 5-го поколения, обеспечивающими до **1 PFLOPS** производительности на FP4.

**Вопрос 6. В чём ключевая особенность памяти DGX Spark?**
**128 ГБ унифицированной памяти LPDDR5X**, которая одновременно и когерентно доступна и CPU, и GPU. Это позволяет загружать модели, которые не поместились бы в 32 ГБ дискретной видеопамяти, но платой за это является пропускная способность **273 ГБ/с**.

**Вопрос 7. Какой максимальный размер модели поддерживает один DGX Spark?**
Один блок рассчитан на модели до **200 миллиардов параметров**. Два блока, соединённых через встроенную сеть ConnectX-7, могут обслуживать модели до **405 миллиардов параметров**.

**Вопрос 8. Что происходит при подаче питания?**
DGX Spark **включается автоматически** при подключении питания. Отдельной кнопки «Вкл» нет. Все периферийные устройства (монитор, клавиатура, мышь, сетевой кабель) должны быть подключены **до** подачи питания.

**Вопрос 9. Какие два способа первоначальной настройки существуют?**
1. **Локальный**: с монитором, клавиатурой и мышью, следуя мастеру на экране.
2. **Сетевой**: DGX Spark создаёт собственную Wi-Fi-сеть, к которой вы подключаетесь с другого компьютера и проходите настройку через браузер.

**Вопрос 10. Обязательно ли иметь монитор для настройки?**
Нет. Сетевой режим позволяет завершить настройку без монитора и клавиатуры. Однако выбор способа доступа касается **только** первоначальной настройки — после завершения вы можете пользоваться устройством любым удобным способом.

**Вопрос 11. Какое подключение к интернету требуется при первой настройке?**
Быстрое и стабильное соединение (Wi-Fi или Ethernet). **Не рекомендуются** гостевые сети с captive portal (отели, аэропорты) и мобильные точки доступа, так как обновления могут прерваться.

**Вопрос 12. Что произойдёт, если прервать установку обновлений при первой настройке?**
Система может быть **повреждена**. NVIDIA прямо предупреждает: не выключайте и не перезагружайте устройство, как только началась загрузка обновлений — процесс нельзя прервать.

**Вопрос 13. Почему при настройке через сеть может не открываться страница `http://spark-xxxx.local`?**
Это частая проблема с Windows и macOS: по умолчанию они могут блокировать обнаружение устройств в локальной сети. В Windows нужно установить для Wi-Fi-сети профиль **«Частная сеть»** и включить «Обнаружение сети». На macOS необходимо разрешить браузеру доступ к локальной сети.

**Вопрос 14. Что делать, если SSID DGX Spark не виден?**
DGX Spark транслирует SSID **только до завершения первоначальной настройки**. Если настройка уже завершена, это нормальное поведение. Если нет — проверьте, включён ли DGX Spark (пингуйте `spark-xxxx`), выключите и включите Wi-Fi на клиентском устройстве, либо выполните цикл питания: зажмите кнопку питания на 5 секунд, подождите 5 секунд, нажмите и отпустите для перезагрузки.

**Вопрос 15. Монитор не определяется при локальной настройке — что делать?**
Попробуйте использовать **HDMI** вместо USB-C/DisplayPort — некоторые мониторы некорректно работают с Spark «из коробки» через USB-C. Также рекомендуется использовать кабели USB-C → DP или USB-C → USB-C из комплекта монитора, либо сертифицированные VESA-кабели.

**Вопрос 16. Почему `nvidia-smi` не показывает использование памяти?**
Это **ожидаемое поведение**. `nvidia-smi` сообщает об использовании памяти только при наличии выделенной VRAM. Поскольку DGX Spark использует **унифицированную архитектуру памяти**, для мониторинга нужно применять `top`, `htop` или `free -h`, либо панель DGX Dashboard по адресу `https://localhost:11000`.

**Вопрос 17. Приложение падает с ошибкой памяти, хотя модель должна помещаться. В чём причина?**
Unified memory может кэшироваться. Проверьте поле `buff/cache` командой `free -h`. Если память «застряла» в кэше, её можно принудительно очистить: `sudo sh -c 'sync; echo 3 > /proc/sys/vm/drop_caches'`.

**Вопрос 18. Какая пропускная способность сети у DGX Spark?**
Встроенный сетевой адаптер **ConnectX-7** (до 200 Гбит/с), а также порт **10 GbE** и **Wi-Fi 7**. Для связи с клиентом Hermes Agent (Geekom A8 Max) рекомендуется использовать проводное соединение 10 GbE или Wi-Fi 7, чтобы пропускная способность сети не стала узким местом.

**Вопрос 19. Сколько энергии потребляет DGX Spark?**
Около **240 Вт** — это сопоставимо с мощной настольной системой, но значительно меньше, чем у серверного оборудования.

**Вопрос 20. Какой объём хранилища у DGX Spark?**
До **4 ТБ NVMe PCIe Gen5** — достаточно для размещения нескольких квантованных моделей и их кэша.

**Вопрос 21. Можно ли использовать DGX Spark как сетевой сервер без прямого доступа?**
Да. После завершения первоначальной настройки доступ по SSH и через API ничем не ограничен. Сетевой режим настройки — это лишь способ завершить первичную конфигурацию, а не постоянное ограничение.

**Вопрос 22. Какие обновления безопасности и ядра приходят на DGX Spark?**
Обновления поставляются через **DGX OS** и включают исправления безопасности, обновления ядра и оптимизации платформы. Рекомендуется регулярно проверять наличие обновлений через DGX Dashboard или стандартные средства Ubuntu.

**Вопрос 23. Влияет ли версия DGX OS на выбор рецепта для vLLM?**
Да, косвенно. Более новые версии DGX OS содержат более свежие драйверы и ядро, что может влиять на совместимость с определёнными сборками vLLM и контейнерами. Перед развёртыванием модели убедитесь, что ваша версия DGX OS соответствует требованиям рецепта.

**Вопрос 24. Какой пароль по умолчанию у DGX Spark?**
Пароля по умолчанию нет — учётная запись создаётся вами в процессе первоначальной настройки. Это ещё одна причина не пропускать мастер First-Time Setup.

**Вопрос 25. Где найти официальную документацию по DGX Spark?**
Основной источник — `docs.nvidia.com/dgx/dgx-spark/`. Раздел «Initial Setup – First Boot» содержит актуальные инструкции по всем сценариям первоначальной настройки.

## Тема 2: Qwen3.8-27B на DGX Spark через vLLM

**Вопрос 1. Что представляет собой Qwen3.8-27B?**
Это **27-миллиардная плотная (dense) модель** семейства Qwen3.8 с гибридным вниманием: только 16 из 64 слоёв используют полное внимание, а 48 слоёв — линейное внимание с постоянным рекуррентным состоянием. Модель является **мультимодальной** (архитектура `Qwen3_5ForConditionalGeneration`) и имеет нативное контекстное окно **262 144 токена** с возможностью расширения до 1 млн.

**Вопрос 2. Почему для DGX Spark рекомендуется именно вариант NVFP4?**
NVFP4 — это 4-битный формат квантования, оптимизированный для архитектуры Blackwell. В этом формате Qwen3.8-27B занимает около **24,6 ГиБ**, что позволяет модели комфортно разместиться в 128 ГБ унифицированной памяти DGX Spark и оставить значительный запас для KV-кэша и других задач.

**Вопрос 3. Сколько памяти занимают веса модели в NVFP4?**
По разным оценкам, веса Qwen3.8-27B (Dense) в NVFP4 занимают примерно **16,5 ГБ**, а полный занимаемый объём с учётом всех компонентов составляет около **24,6 ГиБ**. Это оставляет порядка 40 ГБ и более под KV-кэш и служебные нужды.

**Вопрос 4. Какой минимальный набор компонентов нужен для запуска модели?**
Docker с поддержкой NVIDIA GPU, контейнер с vLLM (версия 0.17.0 или новее) и загруженные веса модели. Официальный рецепт от vLLM для DGX Spark (GB10) является проверенным и рекомендуется как отправная точка.

**Вопрос 5. Какую команду `vllm serve` использует официальный рецепт для DGX Spark?**
Проверенная конфигурация для одного DGX Spark (GB10) выглядит так:
```bash
export VLLM_USE_RUST_FRONTEND=1
vllm serve Qwen/Qwen3.8-27B \
  --max-num-seqs 8 \
  --gpu-memory-utilization 0.8 \
  --tensor-parallel-size 1 \
  --enable-auto-tool-choice \
  --tool-call-parser qwen3_coder \
  --reasoning-parser qwen3 \
  --mm-encoder-tp-mode data
```


**Вопрос 6. Что означает параметр `--gpu-memory-utilization 0.8`?**
vLLM будет использовать до **80%** доступной памяти GPU (в случае DGX Spark — унифицированной памяти) для модели и KV-кэша. Оставшиеся 20% резервируются для системных нужд и других процессов.

**Вопрос 7. Зачем нужен `--tensor-parallel-size 1`?**
Это означает, что модель не разрезается между несколькими GPU, а целиком размещается на одном GB10. Для одного DGX Spark это корректная настройка.

**Вопрос 8. Что делают парсеры `qwen3_coder` и `qwen3`?**
`--tool-call-parser qwen3_coder` включает корректную обработку вызовов инструментов (tool calling), что критически важно для работы Hermes Agent. `--reasoning-parser qwen3` обеспечивает поддержку режима рассуждений (reasoning) модели.

**Вопрос 9. Почему рецепт рекомендует `VLLM_USE_RUST_FRONTEND=1`?**
Экспериментальный Rust-фронтенд vLLM может повысить пропускную способность и снизить задержку, особенно при высокой конкурентности запросов. Если вы столкнётесь с несовместимостью или отсутствием нужных функций, можно переключиться на Python-фронтенд.

**Вопрос 10. Как проверить, что vLLM-сервер запустился и API доступен?**
Выполните на DGX Spark:
```bash
curl -sS http://localhost:8000/v1/models
```
В ответе должен быть JSON-массив `data` с идентификатором обслуживаемой модели. Это стандартная проверка OpenAI-совместимого эндпоинта.

**Вопрос 11. На каком порту по умолчанию работает vLLM?**
По умолчанию vLLM слушает порт **8000**. Именно на этот порт нужно будет настроить Hermes Agent (с указанием `/v1` в конце URL).

**Вопрос 12. Обязательно ли использовать Docker?**
Официальные рецепты vLLM для DGX Spark предполагают запуск в контейнере, но технически можно установить vLLM и в виртуальное окружение. Однако контейнерный путь является **проверенным и воспроизводимым**, поэтому рекомендуется именно он.

**Вопрос 13. Можно ли использовать другой формат квантования, например FP8 или INT4?**
Да, рецепт vLLM предлагает варианты FP8, INT4 и MXFP4. Однако для одного DGX Spark официально рекомендован именно **NVFP4** как оптимальный по соотношению «занимаемая память / производительность».

**Вопрос 14. Что делать, если модель не помещается в память?**
Уменьшите `--gpu-memory-utilization` (например, до 0.7) или сократите `--max-model-len`. NVFP4-версия занимает около 24,6 ГиБ, поэтому в 128 ГБ она должна помещаться с большим запасом, но KV-кэш для длинного контекста может занимать значительный объём.

**Вопрос 15. Как обеспечить доступ к API vLLM с другого компьютера (Geekom A8 Max)?**
vLLM по умолчанию может слушать только `localhost`. Чтобы сделать его доступным по сети, при запуске добавьте флаг `--host 0.0.0.0`. **Обязательно** убедитесь, что порт 8000 открыт в брандмауэре DGX Spark.

**Вопрос 16. Какие риски безопасности связаны с `--host 0.0.0.0`?**
Открытие порта vLLM на все интерфейсы делает API доступным любому в локальной сети. Если в вашей сети есть недоверенные устройства, рассмотрите использование обратного прокси с аутентификацией или ограничьте доступ по IP. Для домашней лаборатории это приемлемый компромисс, но для офисной сети — требует оценки рисков.

**Вопрос 17. Поддерживает ли Qwen3.8-27B вызов инструментов (tool calling)?**
Да, и это критически важно для Hermes Agent. Именно поэтому в команде запуска присутствуют `--enable-auto-tool-choice` и `--tool-call-parser qwen3_coder`. Без них агент не сможет корректно использовать инструменты.

**Вопрос 18. Можно ли увеличить контекстное окно свыше 262K?**
Модель поддерживает расширение до **1 млн токенов**, но это потребует значительного объёма KV-кэша. На одном DGX Spark с 128 ГБ памяти увеличение контекста сокращает доступную память для других задач. Начните со стандартных 262K и увеличивайте только при необходимости.

**Вопрос 19. Как обновить vLLM или сменить модель?**
Остановите текущий контейнер (Ctrl+C), затем запустите новый с обновлённым тегом образа или другим идентификатором модели. Hermes Agent после этого нужно перенастроить на тот же URL — он увидит новую модель через `hermes model`.

**Вопрос 20. Что такое MTP (Multi-Token Prediction) и стоит ли его включать?**
MTP — это встроенная в Qwen3.8-27B голова спекулятивного декодирования, которая может ускорить генерацию. В рецепте vLLM для её активации используется `--speculative-config '{"method":"mtp","num_speculative_tokens":3}'`. Включайте, если хотите снизить задержку, но следите за потреблением памяти.

**Вопрос 21. Нужен ли API-ключ для локального vLLM?**
По умолчанию vLLM не требует API-ключа. Hermes Agent при подключении к кастомному эндпоинту может запросить ключ — в этом случае можно ввести любую заглушку (например, `not-needed`). Если вы запускаете vLLM с флагом `--api-key`, используйте именно этот ключ.

**Вопрос 22. Как мониторить использование памяти и GPU во время работы vLLM?**
Поскольку `nvidia-smi` не показывает память на DGX Spark, используйте `free -h`, `htop` или DGX Dashboard (`https://localhost:11000`). Для мониторинга загрузки GPU можно использовать `nvtop`, если он установлен.

**Вопрос 23. Какая версия transformers требуется для Qwen3.8-27B?**
Требуется **`transformers >= 5.8.0`**, чтобы соответствовать версии, с которой был записан `config.json` модели (для классов процессора Qwen3-VL). vLLM использует собственный `Qwen3_5Config`, но установка правильной версии transformers важна для корректной работы с мультимодальными компонентами.

**Вопрос 24. Что делать, если vLLM падает с ошибкой нехватки памяти при загрузке?**
Убедитесь, что используется именно NVFP4-версия (она значительно компактнее BF16). Если ошибка сохраняется, проверьте, не занята ли память другими процессами (`free -h`), и при необходимости очистите кэш. Также можно снизить `--gpu-memory-utilization`.

**Вопрос 25. Где найти официальный рецепт vLLM для Qwen3.8-27B на DGX Spark?**
Прямая ссылка: `recipes.vllm.ai/Qwen/Qwen3.8-27B?hardware=dgx_spark_gb10`. Дополнительная точка входа — `build.nvidia.com/station/vllm/choose-recipe`, где можно выбрать конфигурацию «One DGX Spark» и получить рекомендованный рецепт.

## Тема 3: Hermes Agent на Geekom A8 Max (Windows) с подключением к DGX Spark

**Вопрос 1. Что такое Hermes Agent?**
Это открытый самохостируемый ИИ-агент от Nous Research с постоянной памятью, автономным созданием навыков и встроенным циклом обучения. Он может подключаться к облачным API и к локальным self-hosted эндпоинтам, включая vLLM.

**Вопрос 2. Поддерживает ли Hermes Agent Windows нативно?**
Существует ранняя нативная установка для Windows через PowerShell, но **официально рекомендуется WSL2** как более стабильный и проверенный путь. WSL2-установка использует тот же установочный скрипт, что и Linux/macOS.

**Вопрос 3. Какая команда установки Hermes Agent в WSL2?**
```bash
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
```
После установки необходимо перезагрузить оболочку: `source ~/.bashrc` (или `~/.zshrc`).

**Вопрос 4. Какую команду использовать для настройки провайдера модели?**
Основная команда — **`hermes model`**. Она запускает интерактивный мастер выбора провайдера и модели. Для self-hosted решений нужно выбрать пункт **«Custom endpoint»**.

**Вопрос 5. Какие три поля нужно заполнить при выборе Custom endpoint?**
1. **API base URL** — адрес вашего vLLM-сервера, например `http://<IP-адрес_DGX_Spark>:8000/v1`.
2. **API key** — для локального vLLM обычно не требуется; можно ввести заглушку, если мастер настаивает.
3. **Model name** — идентификатор обслуживаемой модели (например, `Qwen/Qwen3.8-27B` или `Inferact/Qwen3.8-27B-NVFP4`).

**Вопрос 6. Где Hermes Agent хранит конфигурацию?**
В WSL2 конфигурация и данные хранятся в **`~/.hermes/`**. Файл `config.yaml` содержит настройки провайдера и модели, а `.env` — ключи API (если используются).

**Вопрос 7. Можно ли настроить Hermes Agent неинтерактивно, через конфиг-файл?**
Да. Если вы работаете в неинтерактивной SSH-сессии или хотите автоматизировать настройку, используйте команды:
```bash
hermes config set model.provider custom
hermes config set model.base_url http://<IP_DGX_Spark>:8000/v1
hermes config set model.default <model-handle>
```

**Вопрос 8. Как переключить Hermes Agent на другую модель после смены модели в vLLM?**
Остановите vLLM, запустите его с новой моделью, затем выполните `hermes model`, снова выберите Custom endpoint и укажите тот же URL. Hermes обнаружит доступные модели на эндпоинте и позволит выбрать новую.

**Вопрос 9. Какие переменные окружения можно использовать вместо мастера настройки?**
`OPENAI_BASE_URL` — базовый URL кастомного эндпоинта (vLLM, SGLang и т.д.), и `OPENAI_API_KEY` — ключ для этого эндпоинта. Эти переменные можно задать в `~/.hermes/.env`.

**Вопрос 10. Нужно ли открывать порт 8000 в брандмауэре Windows на Geekom A8 Max?**
Нет. Geekom A8 Max является **клиентом** и инициирует исходящие соединения к DGX Spark. Брандмауэр на клиенте обычно не блокирует исходящий трафик. Открывать порт нужно на **DGX Spark** (входящие соединения на порт 8000), если используется файрвол.

**Вопрос 11. Как проверить, что Hermes Agent видит модель на DGX Spark?**
Запустите тестовый запрос:
```bash
hermes -z "Reply exactly MODEL_OK"
```
Если агент отвечает осмысленно, связка работает. Также можно выполнить `curl -sS http://<IP_DGX_Spark>:8000/v1/models` с клиентской машины, чтобы убедиться в сетевой доступности эндпоинта.

**Вопрос 12. Что делать, если Hermes Agent не может подключиться к vLLM?**
Проверьте по порядку: (1) запущен ли vLLM и слушает ли он `0.0.0.0:8000`, (2) доступен ли порт 8000 с Geekom A8 Max (`curl` или `telnet`), (3) не блокирует ли брандмауэр DGX Spark входящие соединения, (4) правильно ли указан URL с `/v1` в конце.

**Вопрос 13. Почему важно, чтобы vLLM был запущен до установки Hermes?**
При настройке Hermes через `hermes model` агент обращается к эндпоинту, чтобы получить список доступных моделей. Если сервер не запущен, мастер не сможет корректно определить модель. NVIDIA явно указывает: модель должна обслуживаться **до** запуска установщика Hermes.

**Вопрос 14. Какие инструменты (tools) можно включить в Hermes Agent?**
Hermes поддерживает веб-поиск, автоматизацию браузера, доступ к терминалу, файловые операции, выполнение кода и другие инструменты. Управление осуществляется командой `hermes tools` с интерактивным выбором.

**Вопрос 15. Как обновить Hermes Agent?**
Команда `hermes update` загружает последнюю версию, применяет изменения зависимостей и перезапускает службу шлюза.

**Вопрос 16. Как удалить Hermes Agent и сохранить данные?**
`hermes uninstall` удаляет установку и службу шлюза, но по умолчанию сохраняет `~/.hermes/` (конфигурацию, историю, навыки). Для полного удаления выберите «Full uninstall» в мастере.

**Вопрос 17. Можно ли использовать Hermes Agent с Telegram или Discord?**
Да. После того как базовый CLI-чат заработает, можно настроить шлюз для подключения к Telegram, Discord, Slack и другим платформам через `hermes gateway setup`.

**Вопрос 18. Что такое «Blank Slate» установка и как включить инструменты?**
Некоторые установки Hermes начинаются с отключёнными инструментами («Blank Slate»). Чтобы включить их, выполните `hermes tools` и активируйте нужные пункты (пробел — переключение, Enter — подтверждение).

**Вопрос 19. Безопасно ли передавать API-ключи в `~/.hermes/.env`?**
Файл `.env` в домашней директории WSL2 доступен только вашему пользователю. Это стандартная практика для локальных инструментов. Не коммитьте `.env` в Git и не передавайте его третьим лицам.

**Вопрос 20. Почему Hermes Agent может работать медленно при обращении к DGX Spark?**
Узким местом может быть сеть. Если Geekom A8 Max подключён по Wi-Fi, а DGX Spark — по Ethernet, задержка и пропускная способность могут ограничивать скорость генерации. Для наилучшей производительности используйте проводное соединение (10 GbE) между клиентом и сервером.

**Вопрос 21. Можно ли запустить Hermes Agent прямо на DGX Spark, а не на Geekom?**
Да, Hermes Agent можно установить непосредственно на DGX Spark (Linux/arm64) и подключать его к `http://localhost:8000/v1`. NVIDIA предоставляет официальный playbook для такой конфигурации. Ваш сценарий с Geekom A8 Max как клиентом также полностью работоспособен.

**Вопрос 22. Какая версия Hermes Agent актуальна?**
В результатах поиска упоминаются версии `v2026.5.16` / `v0.14.0` и новее. Рекомендуется использовать последнюю стабильную версию, устанавливаемую через официальный скрипт.

**Вопрос 23. Поддерживает ли Hermes Agent локальные модели, отличные от Qwen?**
Да, Hermes Agent совместим с любым OpenAI-совместимым эндпоинтом. Вы можете обслуживать через vLLM другие модели (например, Qwen3.6-35B-A3B, упомянутую в playbook NVIDIA) и переключать Hermes на них через `hermes model`.

**Вопрос 24. Нужно ли настраивать прокси или специальные маршруты для связи WSL2 с DGX Spark?**
Обычно нет. WSL2 по умолчанию использует NAT-сеть, но исходящие соединения к локальной сети (DGX Spark) работают нормально. Если вы используете сложную сетевую конфигурацию, убедитесь, что подсеть DGX Spark доступна из WSL2 (проверьте `ip route` внутри WSL2).

**Вопрос 25. Где найти официальную документацию по Hermes Agent?**
Основной источник — `hermes-agent.nousresearch.com/docs/`. Ключевые разделы: Quickstart, LLM and Model Providers, Installation guide. Дополнительно NVIDIA предоставляет playbook по интеграции Hermes с DGX Spark в репозитории `github.com/NVIDIA/dgx-spark-playbooks`.

```
  [Geekom A8 Max, Windows]                       [NVIDIA DGX Spark, Linux]
  ┌────────────────────────────┐                ┌──────────────────────────┐

  └────────────────────────────┘                └──────────────────────────┘
```

Ключевой принцип: **DGX Spark — это сервер инференса, Geekom A8 Max — клиент-агент.** Соединение происходит по локальной сети через OpenAI-совместимый HTTP API.

## Этап 1. Первоначальная настройка DGX Spark (First-Time Setup)

### 1.1. Подготовка перед подачей питания

> ⚠️ **Критически важно:** DGX Spark **включается автоматически** при подаче питания. Все периферийные устройства — монитор, клавиатура, мышь, сетевой кабель — должны быть подключены **до** подключения блока питания.

Подключите:
- Монитор (предпочтительно через **HDMI**, если USB-C/DisplayPort не определяется).
- Клавиатуру и мышь (USB или Bluetooth).
- Сетевой кабель Ethernet (если планируете проводное подключение — сделайте это сразу, чтобы избежать проблем с подключением позже).
- Только после этого подключите блок питания.

### 1.2. Выбор способа доступа

У вас два варианта, и выбор касается **только** первоначальной настройки — после завершения вы сможете пользоваться DGX Spark любым способом:

| Способ | Что нужно | Когда выбирать |
|---|---|---|
| **Локальный** | Монитор, клавиатура, мышь | Если есть физический доступ и периферия |
| **Сетевой** | Другой компьютер в той же сети | Если DGX Spark будет работать «headless» в серверной роли |

Для сетевого способа DGX Spark создаст Wi-Fi-сеть, к которой нужно подключиться с ноутбука или ПК. Данные для подключения (SSID и пароль) указаны в руководстве пользователя.

### 1.3. Прохождение мастера настройки

Мастер проведёт вас через шаги:
1. Выбор языка, часового пояса, раскладки клавиатуры.
2. Принятие лицензионного соглашения.
3. Создание учётной записи (имя пользователя и пароль) — **пароля по умолчанию нет**, вы создаёте его сами.
4. Настройка имени хоста.
5. Подключение к сети Интернет (Wi-Fi или Ethernet).
6. **Загрузка и установка критических обновлений** — самый продолжительный этап.

> ⚠️ **Не выключайте и не перезагружайте DGX Spark во время установки обновлений.** NVIDIA прямо предупреждает: процесс нельзя прервать, а отключение питания может повредить систему.

### 1.4. Типичные проблемы первого запуска и их решение

| Проблема | Причина | Решение |
|---|---|---|
| **SSID не виден** | Настройка уже завершена, или Wi-Fi-адаптер клиента завис | SSID транслируется только до завершения настройки. Перезагрузите Wi-Fi на клиенте или выполните цикл питания DGX Spark |
| **`spark-xxxx.local` не открывается** | Windows/macOS блокируют локальное обнаружение | Windows: профиль сети → «Частная», включить «Обнаружение сети». macOS: разрешить браузеру доступ к локальной сети |
| **Монитор не определяется** | Проблема совместимости USB-C/DP | Попробуйте **HDMI** или используйте сертифицированные VESA-кабели |
| **Нет доступа к интернету при настройке** | Captive portal или нестабильная сеть | Используйте стабильное проводное соединение или домашний Wi-Fi. Гостевые сети и мобильные точки доступа не рекомендуются |

### 1.5. Проверка после настройки

После завершения настройки и перезагрузки войдите в систему и проверьте:
```bash
# Версия ОС и ядра
lsb_release -a
uname -r

# Доступность GPU
nvidia-smi --query-gpu=name --format=csv,noheader

# Сетевые интерфейсы и IP-адрес
ip a
# или
hostname -I
```
Запомните **IP-адрес DGX Spark** в локальной сети — он понадобится для настройки Hermes Agent.

## Этап 2. Развертывание Qwen3.8-27B на DGX Spark через vLLM

### 2.1. Почему именно NVFP4 и официальный рецепт

Для одного DGX Spark NVIDIA рекомендует модель **Qwen3.8-27B в квантовании NVFP4**. Это 4-битный формат, оптимизированный под Blackwell, который занимает около **24,6 ГиБ** и оставляет достаточно памяти под KV-кэш и системные нужды.

Использование **проверенного рецепта** критически важно: не все комбинации версии vLLM, формата квантования и параллелизма совместимы. Рецепт с `recipes.vllm.ai` для `dgx_spark_gb10` протестирован и гарантирует работоспособность.

### 2.2. Подготовка окружения

Убедитесь, что на DGX Spark установлены:
- **Docker** с поддержкой NVIDIA GPU (NVIDIA Container Toolkit).
- **vLLM** версии **0.17.0 или новее** (если используется контейнер — он уже содержит нужную версию).
- **`transformers >= 5.8.0`** — требование рецепта, связанное с процессором Qwen3-VL.

### 2.3. Запуск vLLM-сервера

Используйте официальную команду из рецепта для DGX Spark (GB10):

```bash
export VLLM_USE_RUST_FRONTEND=1

vllm serve Qwen/Qwen3.8-27B \
  --max-num-seqs 8 \
  --gpu-memory-utilization 0.8 \
  --tensor-parallel-size 1 \
  --enable-auto-tool-choice \
  --tool-call-parser qwen3_coder \
  --reasoning-parser qwen3 \
  --mm-encoder-tp-mode data
```

**Что делает каждый параметр:**
- `VLLM_USE_RUST_FRONTEND=1` — включает экспериментальный Rust-фронтенд для лучшей пропускной способности (при проблемах можно убрать).
- `--max-num-seqs 8` — ограничивает количество одновременных последовательностей.
- `--gpu-memory-utilization 0.8` — использует до 80% памяти GPU/унифицированной памяти.
- `--tensor-parallel-size 1` — модель целиком на одном GB10.
- `--enable-auto-tool-choice` + `--tool-call-parser qwen3_coder` — **обязательны для Hermes Agent** (включают tool calling).
- `--reasoning-parser qwen3` — поддержка режима рассуждений.

> 💡 **Если вы работаете в контейнере**, команда `vllm serve` выполняется внутри контейнера. Следуйте инструкциям рецепта по монтированию модели и пробросу портов.

### 2.4. Обеспечение сетевого доступа к API

По умолчанию vLLM может слушать только `localhost`. Чтобы Geekom A8 Max мог подключиться, добавьте флаг **`--host 0.0.0.0`**:

```bash
vllm serve Qwen/Qwen3.8-27B \
  --host 0.0.0.0 \
  --port 8000 \
  # ... остальные параметры из рецепта
```

> ⚠️ **Безопасность:** `0.0.0.0` открывает API для всех устройств в локальной сети. Убедитесь, что сеть доверенная. Если в сети есть недоверенные устройства, рассмотрите reverse-proxy с аутентификацией.

### 2.5. Проверка работы API

С самого DGX Spark:
```bash
curl -sS http://localhost:8000/v1/models
```

С Geekom A8 Max (после того как узнаете IP-адрес DGX Spark):
```bash
curl -sS http://<IP_адрес_DGX_Spark>:8000/v1/models
```

В ответе должен быть JSON с массивом `data`, содержащим идентификатор обслуживаемой модели. Если запрос с клиента не проходит — проверьте брандмауэр на DGX Spark и доступность порта 8000.

### 2.6. Устранение неполадок vLLM на DGX Spark

| Симптом | Вероятная причина | Решение |
|---|---|---|
| **OOM при загрузке модели** | Недостаточно памяти или выбран BF16-вариант | Используйте **NVFP4**-версию. Снизьте `--gpu-memory-utilization` до 0.7. Проверьте `free -h` |
| **`nvidia-smi` показывает «Not Supported»** | Унифицированная память DGX Spark | Это нормально. Используйте `free -h`, `htop` или DGX Dashboard |
| **Память «заканчивается», хотя модель должна помещаться** | Кэш `buff/cache` занимает память | Очистите кэш: `sudo sh -c 'sync; echo 3 > /proc/sys/vm/drop_caches'` |
| **Hermes не видит tool calling** | Отсутствуют парсеры | Убедитесь, что в команде есть `--enable-auto-tool-choice` и `--tool-call-parser qwen3_coder` |

## Этап 3. Установка и настройка Hermes Agent на Geekom A8 Max (Windows)

### 3.1. Установка WSL2

Откройте **PowerShell от имени администратора** и выполните:
```powershell
wsl --install
```
После перезагрузки установите дистрибутив Ubuntu из Microsoft Store, если он не установился автоматически. WSL2 — официально рекомендуемый путь для Hermes Agent на Windows.

### 3.2. Установка Hermes Agent внутри WSL2

Откройте терминал Ubuntu (WSL2) и выполните:
```bash
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
```

После завершения перезагрузите оболочку:
```bash
source ~/.bashrc   # или source ~/.zshrc
```


### 3.3. Настройка подключения к DGX Spark

Запустите мастер настройки:
```bash
hermes model
```

В мастере:
1. При выборе провайдера укажите **«Custom endpoint»** (Пользовательская конечная точка).
2. **API base URL**: `http://<IP_адрес_DGX_Spark>:8000/v1`
   - **Обязательно** с `/v1` на конце.
   - IP-адрес — тот, который вы узнали на этапе 1.5.
3. **API key**: Для локального vLLM без `--api-key` можно оставить пустым или ввести заглушку (например, `not-needed`).
4. **Model name**: Выберите из списка, который Hermes получит с эндпоинта. Если список пуст — проверьте доступность API (шаг 2.5). Ожидаемый идентификатор: `Qwen/Qwen3.8-27B` (или тот, который вы обслуживаете).

**Альтернатива — неинтерактивная настройка:**
```bash
hermes config set model.provider custom
hermes config set model.base_url http://<IP_адрес_DGX_Spark>:8000/v1
hermes config set model.default Qwen/Qwen3.8-27B
```


### 3.4. Проверка связки

Выполните тестовый запрос:
```bash
hermes -z "Reply exactly MODEL_OK"
```

Если агент отвечает осмысленно — связка работает. Если нет, проверьте по порядку:
- Запущен ли vLLM на DGX Spark (`curl http://localhost:8000/v1/models` на самом Spark).
- Доступен ли порт 8000 с Geekom (`curl http://<IP_DGX_Spark>:8000/v1/models`).
- Не блокирует ли брандмауэр DGX Spark входящие соединения.
- Правильно ли указан URL с `/v1`.

### 3.5. Настройка инструментов (опционально)

Если установка была «Blank Slate» (без инструментов), включите их:
```bash
hermes tools
```
Используйте **пробел** для переключения и **Enter** для подтверждения. Доступны веб-поиск, браузер, терминал, файлы, выполнение кода и другие.

### 3.6. Управление и обслуживание

| Действие | Команда |
|---|---|
| **Переключить модель** | `hermes model` (повторно выбрать Custom endpoint) |
| **Обновить Hermes** | `hermes update` |
| **Просмотреть конфигурацию** | `cat ~/.hermes/config.yaml` |
| **Задать переменные окружения** | Редактировать `~/.hermes/.env` (`OPENAI_BASE_URL`, `OPENAI_API_KEY`) |
| **Удалить с сохранением данных** | `hermes uninstall` |

## Ключевые предупреждения (сводка)

1. **Не прерывайте установку обновлений при First-Time Setup** — это может повредить систему.
2. **Подключайте периферию до подачи питания** — DGX Spark стартует автоматически.
3. **Используйте только проверенные рецепты vLLM** — произвольные комбинации параметров могут не работать.
4. **Не забывайте `/v1` в URL** при настройке Hermes — без него API не будет распознан.
5. **`nvidia-smi` на DGX Spark не показывает память** — это не ошибка, а следствие унифицированной архитектуры.
6. **Пароля по умолчанию нет** — учётная запись создаётся вами при первой настройке.
