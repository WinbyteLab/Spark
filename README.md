### Архитектура решения

*   **Сервер (DGX Spark, Linux)**: Запускает Qwen3.8-27B с помощью vLLM, который создает **OpenAI-совместимый API** (обычно на порту `8000`).
*   **Клиент (Geekom A8 Max, Windows)**: Запускает Hermes Agent, который подключается к этому удаленному API, как к любому другому облачному провайдеру.

---

### Шаг 1: Развертывание Qwen3.8-27B на DGX Spark

NVIDIA подготовила официальные рецепты для запуска этой модели на DGX Spark с помощью vLLM.

1.  **Перейдите на страницу рецептов**: Откройте официальную страницу NVIDIA Build для vLLM: [Serve LLMs with vLLM](https://build.nvidia.com/station/vllm/choose-recipe).
2.  **Выберите конфигурацию**: В таблице выберите строку **«One DGX Spark»** (Один DGX Spark).
3.  **Используйте рекомендованный рецепт**: Для вашего устройства рекомендуется модель **`Qwen3.8-27B NVFP4`**. Это квантованная версия, которая оптимально помещается в память одного DGX Spark.
4.  **Скопируйте и выполните команды**: На странице рецепта (по ссылке `recipes.vllm.ai`) будут представлены готовые команды для скачивания модели, запуска Docker-контейнера и выполнения команды `vllm serve`. Скопируйте и выполните их в терминале DGX Spark.
5.  **Проверьте работу API**: После запуска сервер vLLM будет доступен по адресу `http://<IP-адрес_DGX_Spark>:8000`. Вы можете проверить его, отправив запрос с самого DGX Spark:

```bash
    curl http://localhost:8000/v1/models
```

В ответе вы должны увидеть имя вашей модели (например, `Qwen/Qwen3.8-27B`).

---

### Шаг 2: Установка Hermes Agent на Geekom A8 Max (Windows)

Хотя Hermes Agent имеет раннюю бета-версию для нативной установки на Windows, официальная документация **не поддерживает** этот способ и рекомендует использовать **WSL2** (Windows Subsystem for Linux). Это наиболее стабильный путь.

1.  **Установите WSL2**: Если он еще не установлен, откройте PowerShell от имени администратора и выполните:

```powershell
    wsl --install
```
    После перезагрузки системы установите дистрибутив Ubuntu из Microsoft Store, если это не произошло автоматически.
2.  **Установите Hermes Agent в WSL2**: Откройте терминал Ubuntu (WSL2) и выполните официальную команду установки:

```bash
    curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
```
    Этот скрипт установит все необходимые зависимости, включая Python и `uv`.

---

### Шаг 3: Подключение Hermes Agent к вашему DGX Spark

Теперь нужно настроить Hermes так, чтобы он использовал вашу модель на DGX Spark.

1.  **Запустите мастер настройки**: В терминале WSL2 выполните:

```bash
    source ~/.bashrc  # или source ~/.zshrc
    hermes setup
```
2.  **Выберите «Custom endpoint»**: В мастере настройки при выборе провайдера укажите **«Custom endpoint»** (Пользовательская конечная точка) или аналогичный пункт для self-hosted решений.
3.  **Введите данные вашего сервера**:
    *   **Base URL (Базовый URL)**: `http://<IP-адрес_DGX_Spark>:8000/v1`
    *   **API Key (Ключ API)**: Для локального сервера vLLM ключ обычно не требуется. Оставьте поле пустым или введите любое значение-заглушку (например, `not-needed`), если Hermes настаивает на вводе.
4.  **Укажите модель**: Когда Hermes запросит имя модели, введите идентификатор, который вы видели на шаге 1 (например, `Qwen/Qwen3.8-27B`).

После этого Hermes Agent будет отправлять все запросы на ваш DGX Spark.

---

### Важные моменты для успешного подключения

*   **Сетевое взаимодействие**: Убедитесь, что Geekom A8 Max и DGX Spark находятся в одной локальной сети. Узнать IP-адрес DGX Spark можно командой `ip a` или `hostname -I` в его терминале.
*   **Брандмауэр**: Проверьте, что на DGX Spark не блокируется входящий трафик на порт `8000`. Если брандмауэр включен, добавьте правило для этого порта.
*   **Производительность**: Скорость генерации будет зависеть от пропускной способности вашей локальной сети (Ethernet или Wi-Fi). Для наилучшей производительности рекомендуется использовать проводное соединение.
*   **Альтернатива**: Если вы не хотите использовать WSL2, можно попробовать нативную установку для Windows (ранняя бета) через PowerShell, но стабильность работы не гарантируется.

Если на каком-либо из этапов возникнут вопросы, спрашивайте.
