# Этап 4: Настройка сети и изоляция DGX Spark

### Цель этапа

Настроить DGX Spark для работы в качестве выделенного, изолированного сервера с фиксированным IP-адресом, доступного по кабелю RJ45, и с полностью заблокированным доступом в интернет, сохранив при этом функциональность для локальной сети.

### Целевая архитектура

| Компонент | Параметр | Примечание |
| :--- | :--- | :--- |
| **Интерфейс** | Проводной RJ45 (например, `enP7s7` или `enp1s0f0np0`) | Основной интерфейс для связи с клиентом (Geekom A8 Max) |
| **IP-адрес** | `10.0.0.50/24` (пример) | Статический, назначается через Netplan |
| **Шлюз** | `10.0.0.1` (ваш роутер) | Используется только для маршрутизации внутри локальной сети |
| **Доступ в интернет** | **Заблокирован** | Исходящие запросы во внешний мир запрещены |
| **Доступ по локальной сети** | Разрешён (SSH, порт `8000`) | Только для доверенных устройств из подсети `10.0.0.0/24` |
| **Docker** | Изолирован от UFW | Требует отдельной настройки для корректной работы правил |

Проверьте статус интерфейса:

```bash
ip -br link
```

Флаг -br (brief) выводит информацию компактно, по одной строке на интерфейс. В результатах вы увидите что-то похожее на вывод из документации NVIDIA для DGX Spark

```bash
lo               UNKNOWN        00:00:00:00:00:00 <LOOPBACK,UP,LOWER_UP>
enP7s7           UP             30:c5:...         <BROADCAST,MULTICAST,UP,LOWER_UP>
enp1s0f0np0      UP             30:...            <BROADCAST,MULTICAST,UP,LOWER_UP>
```

## Часть 1: Настройка статического IP-адреса через Netplan

Для назначения постоянного IP-адреса мы будем использовать **Netplan** — стандартный инструмент в Ubuntu 24.04. **Важно:** не редактируйте существующие файлы конфигурации (например, созданные NetworkManager), а создайте новый файл с более высоким приоритетом.

### Шаг 1.1: Идентификация сетевого интерфейса

Выполните команду, чтобы найти имя вашего проводного интерфейса:

```bash
ip -br addr
```
Найдите интерфейс, который находится в состоянии `UP` и имеет соединение. В примерах ниже используется `enP7s7`, но **замените его на ваше актуальное имя**, если оно отличается (например, `enp1s0f0np0`).

### Шаг 1.2: Создание конфигурационного файла Netplan

Создайте новый файл с высоким приоритетом, чтобы он применялся поверх других настроек:
```bash
sudo nano /etc/netplan/99-static-ip.yaml
```

Вставьте следующую конфигурацию, адаптировав её под ваши нужды:
```yaml
network:
  version: 2
  ethernets:
    enP7s7: # <-- ЗАМЕНИТЕ на ваше имя интерфейса
      dhcp4: false
      dhcp6: false
      addresses:
        - 10.0.0.50/24
      routes:
        - to: default
          via: 10.0.0.1 # <-- IP-адрес вашего роутера
      nameservers:
        addresses: [10.0.0.1] # <-- Локальный DNS (роутер)
```

> **💡 Ключевой нюанс для изоляции:** Если вы хотите, чтобы DGX Spark **не имел даже потенциальной возможности** выйти в интернет через этот шлюз, **удалите блок `routes`**. В этом случае система будет знать только о локальной подсети `10.0.0.0/24`, но не будет иметь маршрута по умолчанию во внешний мир.

### Шаг 1.3: Применение конфигурации

Установите правильные права и примените настройки с защитой от ошибок:
```bash
sudo chmod 600 /etc/netplan/99-static-ip.yaml
sudo netplan try
```
Если в течение 120 секунд соединение не будет потеряно, изменения применятся автоматически. Для принудительного применения используйте `sudo netplan apply`.

## Часть 2: Ограничение доступа в интернет с помощью UFW

Теперь настроим межсетевой экран. Наша цель — разрешить входящие подключения **только** из локальной сети и запретить **любые** исходящие соединения во внешний мир.

### Шаг 2.1: Базовая настройка UFW

Выполните последовательность команд для создания строгой политики:
```bash
# Сброс предыдущих правил
sudo ufw --force reset

# Политика по умолчанию: запретить весь входящий и исходящий трафик
sudo ufw default deny incoming
sudo ufw default deny outgoing

# Разрешить входящие подключения из локальной подсети
# SSH (для управления)
sudo ufw allow from 10.0.0.0/24 to any port 22 proto tcp
# API vLLM (для Hermes Agent)
sudo ufw allow from 10.0.0.0/24 to any port 8000 proto tcp

# Разрешить исходящие подключения ТОЛЬКО в локальную сеть
sudo ufw allow out to 10.0.0.0/24

# Включить UFW
sudo ufw enable
```
Эта конфигурация гарантирует, что DGX Spark сможет общаться только с устройствами в подсети `10.0.0.0/24` и не сможет инициировать соединения с внешним миром.

### Шаг 2.2: ⚠️ Критически важный нюанс: Docker и UFW

**Docker по умолчанию обходит правила UFW.** Это происходит потому, что Docker вставляет свои собственные правила в цепочку `iptables` (`DOCKER-USER`), которые обрабатываются до правил UFW. В результате контейнер, запущенный с флагом `-p 8000:8000`, может стать доступным извне, даже если UFW блокирует порт 8000.

Чтобы ваши правила UFW работали для vLLM, запущенного в Docker, у вас есть два основных пути:

1.  **Использовать `--network host` (рекомендуемый и самый простой):** При запуске контейнера vLLM добавьте флаг `--network host`. В этом случае контейнер не будет использовать мостовую сеть Docker, а его сетевой стек станет частью хост-системы. Весь трафик будет проходить через стандартные правила UFW.
    ```bash
    # Пример запуска vLLM с host-сетью
    docker run --gpus all --network host ...
    ```

2.  **Настроить цепочку `DOCKER-USER`:** Если вы не можете использовать `--network host`, необходимо добавить правила в цепочку `DOCKER-USER`, чтобы ограничить доступ к портам контейнера. Это более сложный путь, но он позволяет сохранить изоляцию сети Docker.

**Для вашего сценария настоятельно рекомендуется использовать `--network host`**, так как это значительно упрощает конфигурацию и гарантирует, что ваши правила UFW будут работать.

## Часть 3: Обеспечение полностью автономной работы (Offline-режим)

После того как доступ в интернет заблокирован, все необходимые компоненты (модель, Docker-образы) должны быть загружены **заранее**. Вот как это сделать:

### Шаг 3.1: Предварительная загрузка модели

Перед включением блокировки UFW скачайте модель Qwen3.8-27B и её зависимости в локальный кэш Hugging Face:
```bash
# Выполните эту команду, пока у DGX Spark еще есть доступ в интернет
huggingface-cli download Qwen/Qwen3.8-27B --local-dir /path/to/your/model/cache
```
После этого vLLM сможет загружать модель из локального кэша, не обращаясь к сети.

### Шаг 3.2: Настройка vLLM для работы в офлайн-режиме

При запуске vLLM установите переменные окружения, которые запретят библиотекам пытаться выйти в сеть:
```bash
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1
export VLLM_NO_USAGE_STATS=1 # Отключает отправку анонимной статистики
```
Эти переменные гарантируют, что vLLM и Hugging Face Transformers будут использовать только локальные файлы и не будут пытаться проверить обновления или отправить телеметрию.

## Часть 4: Верификация конфигурации

Выполните следующие проверки, чтобы убедиться, что всё работает как задумано.

1.  **Проверка IP-адреса:**
    ```bash
    ip -br addr show enP7s7
    ```
    Ожидаемый вывод: `10.0.0.50/24` (или ваш выбранный адрес).

2.  **Проверка доступности из локальной сети (с Geekom A8 Max):**
    ```bash
    ping 10.0.0.50
    curl http://10.0.0.50:8000/v1/models
    ```
    `ping` должен успешно проходить, а `curl` — возвращать JSON со списком моделей, если vLLM запущен.

3.  **Проверка отсутствия доступа в интернет (на DGX Spark):**
    ```bash
    curl -I --max-time 5 https://www.google.com
    ```
    Ожидаемый результат: **таймаут** или `Connection refused`. Это подтверждает, что исходящий трафик заблокирован.

4.  **Проверка статуса UFW:**
    ```bash
    sudo ufw status verbose
    ```
    Убедитесь, что политики по умолчанию — `deny (incoming)` и `deny (outgoing)`, и что ваши разрешающие правила активны.

## 🛠️ Устранение неполадок

| Проблема | Возможная причина | Решение |
| :--- | :--- | :--- |
| **Нет связи после `netplan apply`** | Ошибка в YAML или неверное имя интерфейса | Используйте `sudo netplan try` для безопасного применения. Проверьте имя через `ip -br addr`. |
| **Hermes Agent не подключается** | UFW блокирует порт 8000 | Убедитесь, что добавлено правило `sudo ufw allow from 10.0.0.0/24 to any port 8000`. |
| **Docker-контейнер доступен извне, несмотря на UFW** | Docker обходит UFW | Используйте `--network host` при запуске контейнера или настройте цепочку `DOCKER-USER`. |
| **vLLM не может загрузить модель** | Нет доступа в интернет, модель не закэширована | Скачайте модель заранее и используйте `HF_HUB_OFFLINE=1`. |
